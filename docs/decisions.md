# Рішення та відкриті питання

## Стартові рішення підготовки

- Один репозиторій з frontend/ та backend/ за планом проєкту.
- Один frontend для студента й організатора; один backend для обох backend-ролей.
- GitHub Actions для CI; окремі гілки й PR з review.
- Стек із плану є робочою основою, а не записом голосування команди.

## Перший sync

- Підтвердити стек та версії Python/Node, менеджери залежностей.
- Визначити авторів перших каркасів frontend і backend.
- Backend Auth + frontend: JWT у HttpOnly cookies, CORS/CSRF і безпечне provisioning користувачів.
- Backend Core + QA: що саме гарантує анонімність, хто має доступ до БД,
  як забезпечується один голос і чи можна його змінити до закриття.
- DevOps + команда: хостинг, бюджет, власники акаунтів і тестове середовище.
- Усі: критерії MVP, день sync та демо.

## Voting Core: рішення тижнів 6–9 (Backend Elections & Voting Core)

Дата: 2026-10-13. Відповідальний: Backend Voting Core. Потребує підтвердження QA та Auth.

- **Інтервал голосування `[starts_at, ends_at)`**; момент прийняття голосу — час обробки під блокуванням рядка. Наслідок: голос, що «застряг» на закритті, не зараховується.
- **Закриття: ручне + таймер + lazy.** Точність забезпечує прийом голосу й блокування, таймер лише фіксує статус.
- **Узгодженість голос ↔ закриття:** голос бере `FOR SHARE`, закриття — `FOR UPDATE` на рядку голосування.
- **Переходи статусів:** `draft→active→closed`, зворотних немає. Повторні адмін-запити ідемпотентні (200, `changed=false`).
- **Публікація результатів — окрема дія** після закриття; організатор бачить підсумки без публікації; можна приховати назад.
- **Запуск вимагає** ≥2 кандидатів, непорожній whitelist і `ends_at` у майбутньому. Після запуску кандидати, виборці й дати заморожені.
- **Журнал — лише агрегати.** Закриття не фіксує розбивку по кандидатах/переможця (до публікації). Окремі голоси й email не логуються. Журнал append-only (тригер).
- **Явка для організатора — лише лічильники**, без списку «хто проголосував» (персональні дані явки поки не віддаються).
- **Нічия:** система не обирає переможця, повертає всіх лідерів.
- **Email у whitelist** — нижній регістр, домен `ALLOWED_EMAIL_DOMAIN`.
- **Production fail-fast:** mock-авторизація, локальна БД, не-https origin, вимкнений таймер — відмова стартувати.
- **Відкрите питання (QA/Auth):** `voted_at` у `voter_participations` зберігається з точністю до мікросекунд — для зменшення ризику зіставлення за часом розглянути округлення до хвилини або видалення поля.
