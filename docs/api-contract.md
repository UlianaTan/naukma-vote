# API-контракт: чернетка для погодження

Статус: пропозиція, endpoints ще не реалізовані. Backend уточнює схеми,
обидва frontend-розробники перевіряють достатність; DevOps фіксує рішення.
OpenAPI FastAPI після появи коду має відповідати погодженому контракту.

| Метод і шлях | Призначення | Доступ |
|---|---|---|
| GET /health | Перевірка роботи процесу без чутливих даних | Публічний |
| GET /auth/login | Почати вхід Google | Публічний |
| GET /auth/callback | Завершити OAuth | Перевірка OAuth |
| GET /me | Поточний користувач | Авторизований |
| GET /elections | Доступні користувачу голосування | Авторизований |
| GET /elections/{id} | Деталі й кандидати | Допущений користувач |
| POST /elections/{id}/votes | Подати один голос | Допущений користувач |
| GET /elections/{id}/results | Агреговані результати | За правилами публікації |
| POST /elections | Створити голосування | Організатор |

До frontend-інтеграції дописати контракти редагування, кандидатів,
кола виборців, закриття й публікації результатів та виходу з акаунта.

Пропозиція запиту голосу: `{"candidateId":"candidate-1"}`.
Backend визначає виборця з сесії, не з userId у тілі запиту.
Пропозиція відповіді: `{"status":"accepted"}` без повторення вибору.
Пропозиція помилки: `{"error":{"code":"ALREADY_VOTED","message":"Ви вже проголосували"}}`.

Узгодити до реалізації: типи ID, HTTP-коди, UTC ISO 8601 для дат,
пагінацію, cookies або JWT, CSRF, CORS, правила доступу до результатів.
Mock-відповіді готує backend разом із frontend після погодження схем.
