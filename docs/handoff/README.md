# Звіти учасників і передача роботи

Handoff — короткий запис про результат етапу, який допомагає команді
зрозуміти, що готове, як це перевірити та що робити далі.

Звіти пишуть усі сім ролей після завершення узгодженого етапу або передачі
роботи іншому учаснику. Наприклад: backend завершив авторизацію, дизайнер
передав прототип, QA завершив раунд перевірок, DevOps підготував staging.
Один етап може охоплювати кілька задач і PR; звіт на кожен commit не потрібен.

## Як додати звіт

1. Скопіюйте [TEMPLATE.md](TEMPLATE.md), не змінюючи сам шаблон.
2. Збережіть поруч як `YYYY-MM-DD-role-stage.md`.
3. Заповніть розділи конкретними результатами. Для непотрібних полів напишіть
   «не застосовується», для невиконаних перевірок — «не перевірено».
4. Додайте файл через PR і посилання на нього в Issue відповідного етапу.
5. Вкажіть, кому потрібен результат і який наступний крок очікується.

Приклади назв (це приклади, а не вже виконані звіти):

- `2026-09-25-devops-ci-setup.md`
- `2026-09-25-backend-auth-login.md`
- `2026-09-25-uiux-voter-prototype.md`
- `2026-09-25-qa-login-testing.md`

Позначення ролей: `backend-auth`, `backend-core`, `frontend-voter`,
`frontend-admin`, `uiux`, `qa`, `devops`. Для кількох звітів однієї ролі
за день використовуйте різні назви етапів. Кожен учасник описує свій внесок.

Пишіть достатньо, щоб колега міг продовжити роботу без відновлення контексту
з чату. Зазначайте PR/commit або версію макета, щоб було зрозуміло, до якого
стану належить звіт. Не включайте секрети та персональні дані.

Якщо передаєте незавершену роботу, звіт усе одно потрібен: чесно позначте
статус і блокери. Такий звіт не означає, що етап завершений.
