## Мета етапу

Реалізувати каркас voter-частини фронтенду: сторінку логіну через Google (домен `@ukma.edu.ua`), стан сесії (вхід/вихід/помилки), і список активних голосувань із трьома обов'язковими UI-станами (завантаження/порожньо/помилка). Критерій готовності: сторінки відкриваються локально, типи й лінт проходять без помилок, mock-дані явно позначені для заміни.

## Що зроблено

- `LoginPage.tsx` — верстка входу, повідомлення про домен `@ukma.edu.ua`, обробка помилки `?error=invalid_domain` в URL.
- `useAuth.tsx` (`AuthProvider` + `useAuth`) — контекст сесії: перевірка поточного користувача (`GET /api/auth/me`), логін-редирект, вихід (`POST /api/auth/logout`).
- `ElectionsListPage.tsx` — список голосувань із станами `loading` / `empty` / `error` / успішний список.
- `useElections.ts` — хук отримання голосувань, наразі на mock-даних (`mocks/elections.ts`).
- Базові типи (`types.ts`): `User`, `Election`, `ElectionStatus`.
- `App.tsx` — підключено роутинг `/login` і `/` (захищений `ProtectedVoterRoute`), роут `/admin` не чіпався.
- Де знайти: `frontend/src/features/voter/`, `frontend/src/lib/api.ts`, `frontend/src/App.tsx`.

## Як перевірено

- Node.js / npm (Windows, локально), Vite dev-сервер.
- `npx tsc --noEmit` — без помилок типів.
- `npm run lint` — без помилок у своїх файлах (окрім попередньої, не пов'язаної з цим PR, помилки в `@/components/ui/button.tsx`).
- Ручна перевірка в браузері (`npm run dev`): `/login` показує коректні повідомлення про помилку домену; список голосувань перевірено в усіх станах через тимчасову підміну `useElections`.
- **Що не перевірялося:** наскрізний флоу з реальним backend (OAuth ще не готовий на момент цього звіту), робота на staging, мобільна адаптивність.

## Як використати результат

Щоб побачити UI локально:
1. `cd frontend && npm install && npm run dev`
2. Відкрити `http://localhost:5173/login` — сторінка входу.
3. Список голосувань захищений (`ProtectedVoterRoute`) — без реального логіну не відкриється; для локального перегляду тимчасово прибрати обгортку `<ProtectedVoterRoute>` в `App.tsx` (не комітити цю зміну).

Коли Backend Auth готовий: підключити реальний `VITE_API_URL` у `.env`, перевірити, що `/api/auth/me`, `/api/auth/google/login`, `/api/auth/logout` відповідають у форматі, закладеному в `useAuth.tsx`.

## Вплив на інших учасників

## Незавершене, обмеження та блокери

- Реальна інтеграція з Google OAuth — заблоковано до готовності PoC від Дзюби Анастасії.
- Заміна mock-даних на реальний API голосувань — заблоковано до готовності ендпоінта від Хомініч Катерини.
- Сторінки самого голосування (`/vote/:id`) та результату — ще не реалізовані, заплановані на наступний тиждень.
- Виявлено окрему проблему конфігурації: `tailwind.config.js` не мав узгоджених кольорів shadcn (`theme.extend.colors`), через що падав dev-сервер у будь-кого локально — запропоновано фікс, потребує окремого review/merge від DevOps.
