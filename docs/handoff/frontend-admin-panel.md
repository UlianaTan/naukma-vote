## Мета етапу
Реалізувати адміністративну навігацію, таблицю списку голосувань та форму створення чернетки голосування (назва, опис, дати, список кандидатів). Додати валідацію форми та тимчасові mock-операції для збереження.

## Що зроблено
- `AdminLayout.tsx` — базовий каркас адмін-панелі з боковою навігацією (Sidebar).
- `AdminElectionsPage.tsx` — сторінка зі списком голосувань. Дані наразі захардкоджені (mock) у вигляді масиву.
- `CreateElectionPage.tsx` — форма створення нового голосування.
  - Реалізовано динамічне додавання/видалення полів для кандидатів (мінімум 2).
  - Додано валідацію: перевірка на заповненість усіх полів та коректність дат (дата завершення > дата початку).
  - Налаштовано стани UI: `submitting`, `error`, `success`.
  - Замість бекенду наразі використовується `setTimeout` для імітації затримки мережі при збереженні.
- `App.tsx` — налаштовано незалежні роути `/admin` для доступу до адмін-панелі в обхід авторизації `AuthProvider` (тимчасове рішення до готовності backend).

## Як перевірено
- `npm run dev` — ручна перевірка у браузері.
- Форма не відправляє дані, якщо поля порожні або дат налаштовані некоректно.
- Динамічне додавання кандидатів працює без збоїв.

## Як використати результат
Для локального перегляду:
1. `cd frontend && npm install && npm run dev`
2. Відкрити `http://localhost:5173/admin` — список виборів.
3. Сторінки адмін-панелі працюють незалежно від OAuth і доступні без входу.

## Вплив на інших учасників
- Очікує ендпоінт від Backend Voting Core: `POST /api/elections` (для збереження чернетки виборів).
- Очікує ендпоінт від Backend Voting Core: `GET /api/elections` (для відображення списку в `AdminElectionsPage`).

## Незавершене, обмеження та блокери
- Інтеграція з реальним бекендом заблокована до готовності ендпоінтів від бекенд-команди. Наразі логіка спирається на локальні `useState` та імітацію запитів.
- Після інтеграції реального логіну (OAuth), роут `/admin` потрібно буде захистити перевіркою на роль адміністратора (Admin Protected Route).
