## Мета етапу
Реалізувати адміністративну навігацію, таблицю списку голосувань та форму створення чернетки голосування (назва, опис, дати, список кандидатів). Додати валідацію форми та тимчасові mock-операції для збереження.

## Що зроблено
- `AdminLayout.tsx` — базовий каркас адмін-панелі з боковою навігацією (Sidebar).
- `AdminElectionsPage.tsx` — сторінка зі списком голосувань на mock-даних.
- `CreateElectionPage.tsx` — форма створення нового голосування:
  - Динамічне додавання та видалення полів для кандидатів (мінімум 2).
  - Валідація заповненості полів та логіки дат (кінець пізніше за початок).
  - Стани UI (`submitting`, `error`, `success`) із затримкою через `setTimeout` для імітації запиту.
- `App.tsx` — підключено роутинг адмін-панелі (`/admin` та `/admin/create`) у спільному `BrowserRouter`. Voter-роути та `AuthProvider` збережено без змін.
- Конфігурація: оновлено `tailwind.config.js` та `src/index.css`, щоб стилі Tailwind/shadcn працювали в dev-режимі; у `tsconfig.app.json` прибрано застарілий `baseUrl`.
- Виправлено помилково створену папку `frontend/@/components/ui/`: `button.tsx` перенесено в `frontend/src/components/ui/`.

## Як перевірено
- Проєкт запущено локально (`npm run dev`); сторінка `/admin` відкривається в браузері: відображаються бокова навігація, таблиця голосувань на mock-даних і застосовані стилі.
- `npx tsc -b` не видає помилок у файлах адмін-панелі. Лишаються дві помилки у чужому файлі `features/voter/hooks/useAuth.tsx` (див. блокери).
- Форма не відправляє дані з порожніми полями або некоректними датами; динамічне додавання кандидатів працює без збоїв.

## Вплив на інших учасників
- Очікує ендпоінти від Backend Voting Core: `GET /api/elections` (список) та `POST /api/elections` (створення).
- Зміни в `tailwind.config.js` та `src/index.css` торкаються стилів усього фронтенду, тому потрібне рев'ю від DevOps (Танчук Уляна).
- Потрібна дія від автора `useAuth` (voter-частина): закомітити `src/lib/api.ts` (див. блокери).

## Незавершене, обмеження та блокери
- **`src/lib/api.ts` відсутній у репозиторії.** Правило `lib/` у `.gitignore` (рядок 17) ігнорує й `frontend/src/lib/`. Через це `tsc -b` падає у `features/voter/hooks/useAuth.tsx` (імпорт `../../../lib/api`). Потрібно замінити правило на `/lib/` і закомітити `api.ts`. Варто перевірити також, чи `src/lib/utils.ts` потрапив у репозиторій.
- Інтеграція з реальним бекендом заблокована до готовності ендпоінтів. Наразі логіка спирається на локальні `useState` та імітацію запитів.
- Кнопки «Редагувати» та «Видалити» в таблиці поки без обробників.
- Після інтеграції реального логіну (OAuth) роут `/admin` потрібно захистити перевіркою на роль адміністратора (Admin Protected Route). До цього часу він доступний без входу.
- Пункт меню «База виборців» (`/admin/voters`) поки без маршруту та сторінки.
- Версії Tailwind: у проєкті встановлено `tailwindcss` 3.x, а актуальний CLI shadcn генерує стилі під Tailwind v4 (`tw-animate-css`, `shadcn/tailwind.css`, OKLCH-змінні). У `src/index.css` використано сумісний із v3 варіант. Потрібне командне рішення: лишитися на v3 чи перейти на v4, інакше наступний `npx shadcn add` може знову зламати збірку стилів.
