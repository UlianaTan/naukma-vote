# Звіт: локальна реєстрація та вхід через пароль поруч із Google

- **Автор:** Codex за завданням власниці репозиторію
- **Роль:** backend-auth / frontend-voter / QA
- **Дата:** 2026-10-21
- **Тиждень курсу:** не застосовується
- **Статус:** локальна реалізація завершена; перевірка на PostgreSQL 18 і деплой не виконані
- **Основа:** `main` на `1f8f7f6`; локальна гілка `feat/email-password-auth`
- **Джерело перенесеного коду:** PR №37, `Auth-and-Sec`, `1c563c8`
- **Кому передається:** власниці проєкту; пізніше DevOps/QA після окремого погодження

## Мета етапу

Додати форми реєстрації та повторного входу за університетською поштою й
окремим паролем, зберігши Google OAuth, реальні API та поточний деплой.
За прямим рішенням власниці підтвердження адреси листом або кодом не додається.
Лише локальні зміни, без commit/push/PR та без змін Render/Neon.

## Що зроблено

- Перенесено Argon2id hashing/verification, schemas, придатну логіку endpoints,
  методів AuthProvider, форми та тести з PR №37, адаптовані до поточного main.
- POST `/api/auth/register` створює користувача з роллю voter та відразу видає
  стандартну сесію. POST `/api/auth/login` із credentials виконує повторний вхід.
- Email нормалізується; точний домен береться з `ALLOWED_EMAIL_DOMAIN`.
  Пароль при створенні — 12–1024 символи; у БД зберігається лише hash.
- Додано адитивну міграцію `d7e8f9a0b1c2` після `9f5d3b8c1a20`.
  Google identity, індекси, ID, ролі й дані виборів не видаляються.
- Збережено Google login/callback і захист CSRF/refresh, включно з відновленням
  простроченої сесії та обмеженим повторенням CSRF mismatch.
- Кеш frontend-сесії очищується при успішній зміні ідентичності; помилка пароля
  не запускає refresh попередньої сесії. Паролі не повертаються в validation errors.
- Форми інтегровані у чинне оформлення; є перемикання режимів, повтор пароля,
  показ/приховування, помилки та блокування кнопок під час запиту.
- Оновлено API-контракт, backend README та схему БД.
- Docker, моки голосування та видалення готових інтеграцій із PR не переносилися.
  Сторонній `frontend/src/lib/.gitkeep` не змінювався.

## Як перевірено

- `npm run lint`, `npm run build`, `npm test`: успіх, 37 frontend-тестів.
- `python -m ruff check .`: успіх.
- `python -m pip check`: сумісні встановлені залежності тестового середовища.
- `python -m unittest discover -s tests -q`: 199 тестів, 184 пройдено,
  15 PostgreSQL-тестів пропущені без TEST_DATABASE_URL. DATABASE_URL примусово
  встановлено на SQLite у пам’яті; реальна база не використовується.
- Перевірено реєстрацію, cookies, нормалізацію адрес, чужі домени, дублікати,
  спробу перезапису Google-акаунта, неправильні паролі, Origin, privacy помилок,
  refresh/logout і запис одного реального бюлетеня через API у тестовій БД.
- Окремий migration test перевіряє upgrade/downgrade без втрати Google identity,
  ID, email, ролі та унікальності на ізольованій SQLite-таблиці.
- Google OAuth regression suite використовує mock Google responses, без реальних
  університетських акаунтів. Password-session cookies перевірені також із staging
  policy Secure/HttpOnly/SameSite=None через HTTPS ASGI test client.
- Браузер: локальний frontend і реальні backend handlers з одноразовою SQLite
  fixture. Перевірено mismatch паролів, реєстрацію → автоматичний вхід → вихід →
  неправильний пароль → успішний повторний вхід → reload зі збереженням сесії.
- Візуально перевірено форми при ширині 390 і 1280 px; горизонтального overflow немає.
- `alembic heads`: єдина голова `d7e8f9a0b1c2`; `git diff --check` і repository checks успішні.

## Як використати результат

Переглянути локальний diff на гілці. Для звичайного локального запуску встановити
оновлені requirements і застосувати міграції до окремої локальної PostgreSQL 18

Контракт і коди помилок — у [API-контракті](../api-contract.md).

## Вплив на інших учасників

Перед майбутнім деплоєм backend потрібна окремо погоджена міграція бази;
readiness перевіряє відповідність новій схемі. Спосіб розгортання, змінні OAuth
і структура frontend/backend сервісів залишаються поточними.

## Незавершене, обмеження та блокери

- Не виконано PostgreSQL 18 migration/concurrency suite локально та новий staging QA.
- Підтвердження володіння поштою не реалізоване за рішенням власниці: домен і формат
  не доводять, хто володіє адресою. Відновлення/зміна пароля й account linking не додані.
- Повторна реєстрація не встановлює пароль Google-акаунту. Автоматичне злиття
  password-акаунта з Google за email заборонене (account_conflict), щоб Google-вхід
  не успадкував пароль, створений без перевірки адреси. Наявні Google-акаунти працюють.
- Не виконано merge, зміни staging, Neon, Render чи реальні голосування.
